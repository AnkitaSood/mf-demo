# mf-demo — Module Federation 2

A cross-framework Micro-Frontend demo using **Module Federation 2** (`@module-federation/enhanced` ecosystem).

| App | Framework | Port | Role |
|-----|-----------|------|------|
| `ng-shell` | Angular 22 + esbuild | 4200 | **Host** (shell) |
| `react-app` | React 19 + Vite | 3000 | **Remote** |
| `vue-app` | Vue 3 + Vite | 3001 | **Remote** |

## Architecture

```
ng-shell (Angular 22)
├── @module-federation/runtime   ← init() + loadRemote() — no webpack needed
├── mf-manifest.json discovery   ← reads http://localhost:3000/mf-manifest.json
│                                         http://localhost:3001/mf-manifest.json
├── /react  → ReactWrapperComponent  → loadRemote('react_app/App')
└── /vue    → VueWrapperComponent    → loadRemote('vue_app/App')

react-app (Vite + React 19)
└── @module-federation/vite
    ├── exposes: { './App': './src/mfe-entry.ts' }
    ├── exports: mount(container) / unmount()
    └── generates: mf-manifest.json

vue-app (Vite + Vue 3)
└── @module-federation/vite
    ├── exposes: { './App': './src/mfe-entry.ts' }
    ├── exports: mount(container) / unmount()
    └── generates: mf-manifest.json
```

## Key Design Decisions

- **No webpack in ng-shell** — `@module-federation/runtime` works as a pure JS runtime with Angular's esbuild builder
- **`mf-manifest.json`** — generated by `@module-federation/vite`, contains module metadata, shared deps, and entry points
- **`mount` / `unmount` pattern** — remotes export framework-agnostic lifecycle functions; React and Vue never touch the shell's bundle
- **Lazy routes** — each MFE is only fetched when its route is first navigated to

## Dev Setup

```bash
# 1. Start remotes first (shell reads their manifests on load)
cd react-app && npm run dev     # → http://localhost:3000
cd vue-app   && npm run dev     # → http://localhost:3001

# 2. Start the shell
cd ng-shell && npm start        # → http://localhost:4200
```

Or from the root (starts all three):
```bash
npm run dev
```

## mf-manifest.json

Each Vite remote serves a `mf-manifest.json` at its root when `manifest: true` is set in the federation config. The ng-shell's `init()` call registers these manifests so `loadRemote('react_app/App')` resolves correctly at runtime.

Example manifest URL: `http://localhost:3000/mf-manifest.json`

## Routes (ng-shell)

All routing is owned by `ng-shell/src/app/app.routes.ts`:

| Path | Component |
|------|-----------|
| `/` | `HomeComponent` (local) |
| `/react` | `ReactWrapperComponent` → loads `react_app/App` |
| `/vue` | `VueWrapperComponent` → loads `vue_app/App` |
